## 2. 技术栈选型

### 2.1 核心技术栈

| 技术组件 | 版本要求 | 核心用途 |
|---------|---------|---------|
| Vue | ≥3.5.0 | 前端核心框架，组合式 API 开发 |
| Vite | ≥6.0.0 | 前端构建工具，快速热更新 |
| Vue Router | ≥4.4.0 | 前端路由管理 |
| Pinia | ≥2.3.0 | 前端状态管理 |
| Element Plus | ≥2.9.0 | 企业级 UI 组件库 |
| Axios | ≥1.7.0 | HTTP 请求库，前后端接口交互 |
| ECharts | ≥5.5.0 | 数据可视化，图表展示 |
| TailwindCss | @latest | 前端界面 UI 样式美化、统一化 |

### 2.2 开发依赖

| 工具 | 版本要求 | 用途 |
|-----|---------|------|
| ESLint | 最新 | 代码规范检查 |
| Prettier | 最新 | 代码格式化 |
| marked | ≥9.0.0 | Markdown 解析渲染 |
| highlight.js | ≥11.0.0 | 代码块语法高亮 |

### 2.3 技术选型说明

- **Vue 3 组合式 API**：现代前端框架，支持更好的 TypeScript 集成和代码组织
- **Element Plus**：企业级组件库，UI 风格简洁实用，适合内部工具类应用
- **TailwindCss**：原子化 CSS 框架，快速实现自定义样式
- **Pinia**：Vue 3 官方推荐的状态管理库，比 Vuex 更轻量简洁
- **Axios**：成熟稳定的 HTTP 请求库，支持请求拦截和响应拦截

### 2.4 UI 技术栈使用规范

#### 2.4.1 分工原则

| 技术 | 职责定位 | 使用场景 |
|-----|---------|---------|
| **Element Plus** | 核心布局与交互组件 | 页面布局、表单组件、按钮、表格、抽屉、弹窗等业务组件 |
| **TailwindCss** | 样式美化与快捷应用 | 间距(margin/padding)、颜色、文字大小、flex布局等样式定制 |

#### 2.4.2 使用规范

**Element Plus 使用规范**：
- 优先使用 Element Plus 提供的组件（如 `el-button`、`el-input`、`el-table` 等）
- 使用 `el-drawer` 作为知识库编辑的抽屉组件
- 使用 `el-dialog` 作为确认提示弹窗
- 使用 `el-form` + `el-form-item` 构建表单
- 使用 `el-message` 或 `ElMessage` 显示操作反馈

**TailwindCss 使用规范**：
- 用于补充 Element Plus 无法覆盖的样式场景
- 常用场景：
  - 自定义间距：`mt-4`、`mb-2`、`p-6`
  - 自定义颜色：`text-gray-600`、`bg-white`
  - 响应式布局：`md:flex`、`lg:block`
  - 文字样式：`text-sm`、`font-bold`
- 避免滥用，保持代码可读性
- 复杂样式仍使用 scoped CSS 或 CSS 变量

#### 2.4.3 样式优先级

```
1. Element Plus 组件默认样式（最低优先级）
2. TailwindCss 工具类（覆盖基础样式）
3. scoped CSS / CSS 变量（特殊场景）
4. 内联 style（紧急修复，慎用）
```

#### 2.4.4 主题适配

- Element Plus 支持亮色/暗色主题切换
- 使用 CSS 变量定义主题色，保持一致性
- TailwindCss 的 `dark:` 前缀支持暗色模式

## 3. 页面规划

### 3.1 页面清单（4 个核心页面）

| 序号 | 页面名称 | 路由路径 | 页面说明 |
|-----|---------|---------|---------|
| 1 | 登录页 | `/login` | 用户登录认证 |
| 2 | 工作台 | `/dashboard` | 首页统计概览 |
| 3 | 知识库管理 | `/knowledge` | 知识库列表管理 |
| 4 | 智能问答 | `/chat` | 知识库问答对话 |

### 3.2 页面详细说明

#### 3.2.1 登录页 (`/login`)

**功能说明**：

- 用户名 + 密码登录（企业内部工具，暂不支持 SSO）
- 登录成功后跳转到工作台
- 错误信息提示（用户名/密码错误）
- 登录状态持久化（Token 存储到 localStorage）

**布局**：

- 居中卡片式登录表单
- 企业风格，简洁大方

#### 3.2.2 工作台 (`/dashboard`)

**功能说明**：

- 展示系统核心统计数据（知识库数量、文档数量、对话数量等）
- 快捷入口跳转到知识库管理或智能问答
- 简单的统计图表（如近 7 天对话趋势）

**布局**：

- 左侧侧边栏 + 右侧内容区
- 顶部显示当前用户信息

#### 3.2.3 知识库管理 (`/knowledge`)

**功能说明**：

- 知识库列表展示（名称、描述、文档数、创建时间）
- 创建知识库（弹窗/抽屉表单）
- 编辑知识库信息
- 删除知识库（确认提示）
- 进入知识库详情（查看文档列表）
- 文档上传（知识库详情页内）
- 文档列表展示（文档名称、状态、处理进度）
- 删除文档

**列表 + 弹窗/抽屉交互模式**：

- 主页面展示列表
- 操作按钮触发抽屉或弹窗
- 表单提交后刷新列表

**布局**：

- 左侧侧边栏 + 右侧内容区
- 顶部：页面标题 + 创建按钮
- 中间：知识库列表表格
- 右侧抽屉：知识库编辑表单
- 知识库详情页：文档列表 + 上传按钮

#### 3.2.4 智能问答 (`/chat`)

**功能说明**：

- 左侧：知识库列表（选择当前问答使用的知识库）
- 右侧：对话区域
  - 对话历史列表（切换不同对话）
  - 当前对话消息展示（用户提问 + AI 回答）
  - 流式打字效果展示 AI 回答
  - 引用溯源展示（引用片段可点击查看来源）
- 提问输入框（支持 Enter 发送）
- 新建对话按钮
- Think 模式处理：默认隐藏思考过程（后续可配置展示）

**布局**：

#### 4.4.2 核心功能详细说明

**P0 优先级 - 核心基础功能**

1. **多轮对话流式渲染**
   - 使用 `fetch` + `ReadableStream` 接收流式响应
   - 实现打字机效果，逐步显示 AI 回答内容
   - 支持中途停止生成（`AbortController`）
   - 生成过程中锁定输入框，防止重复提交
   - 流结束信号识别：`{ type: 'end', chatId: 'xxx' }`

2. **会话生命周期管理**
   - 新建对话：创建新会话，自动切换到新会话
   - 切换会话：点击历史会话加载对话上下文
   - 删除会话：确认提示后删除，同时从列表移除
   - 会话列表按时间倒序排列

3. **标准化输入交互**
   - Shift + 回车：换行
   - 回车：发送消息
   - 一键清空：按钮快速清空输入框
   - 字数上限：提示用户输入字数上限（建议 500-1000 字）

4. **全链路加载状态提示**
   - 检索阶段：显示"正在检索相关文档..."
   - 生成阶段：显示"正在生成回答..."
   - 异常提示：区分服务异常、网络异常、内容为空等场景

#### 4.4.3 P1 优先级 - 重要增强功能

5. **引用溯源与原文对照**
   - AI 回答中用 `[1]`、`[2]` 格式标注引用
   - 回答下方列出引用来源卡片：
     - 来源文档名称
     - 引用片段内容预览
     - 点击高亮展示完整原文
   - 引用数据结构：
     ```javascript
     {
       documentId: string,
       documentName: string,
       content: string,
       score?: number
     }
     ```

6. **检索过程透明化展示**
   - 每条回答显示检索统计："根据 5 个相关片段生成回答"
   - 支持展开查看全量检索片段：
     - 片段内容
     - 相似度分数
     - 来源文档
   - 折叠/展开交互

7. **目标知识库切换**
   - 左侧知识库列表支持勾选/取消
   - 切换后自动清空当前会话上下文
   - 顶部明确显示"当前问答知识库：知识库A、知识库B"
   - 未选择知识库时的提示引导

8. **登录身份与会话隔离**
   - 路由守卫确保未登录用户无法访问
   - API 请求携带 JWT Token
   - 会话列表仅显示当前用户数据
   - 后端按 userId 隔离数据

#### 4.4.4 P2 优先级 - 体验优化功能

10. **对话内容基础操作**
    - 单条回答复制：点击复制按钮，内容复制到剪贴板
    - 单条对话删除：删除单条消息（保留上下文）
    - 清空当前会话：清空所有消息，确认提示

11. **合规免责声明展示**
    - 输入框下方固定文本："AI 回答仅供参考，请以实际情况为准"
    - 超长回答末尾追加："以上内容由 AI 生成，请核实准确性"

#### 4.4.5 P3 优先级 - 增强功能

13. **Markdown 内容格式化渲染**
    - 使用 `marked` 或 `markdown-it` 库解析
    - 支持渲染：标题、列表、表格、代码块、链接、图片等
    - 代码块语法高亮（使用 `highlight.js`）

14. **主题模式切换**
    - 使用 `Element Plus` 的深色主题
    - 支持手动切换：浅色/深色/跟随系统
    - 记住用户偏好（localStorage 存储）
    - 主题状态全局管理（Pinia store）

#### 4.4.6 API 接口对接

| 功能 | API 接口 | 说明 |
|-----|---------|------|
| 发送问题 | `POST /api/v1/chat/ask/stream` | 流式响应 |

#### 4.4.7 流式响应数据结构

**请求格式**：

```javascript
{
  query: string,           // 用户问题
  knowledgeBaseIds: string[] // 选中的知识库 ID 列表
}
```

**流式响应格式（SSE）**：

```
data: {"content": "你好"}

data: {"content": "，"}

data: {"code": 0, "msg": "success", "data": {"type": "end", "chatId": "xxx"}}
```

**Think 模式处理**：

## 5. API 接口对接规范

### 5.1 接口前缀与响应格式

- **接口前缀**：`/api/v1`
- **统一响应格式**：`{ code, msg, data }`

**成功响应**：

```json
{
  "code": 0,
  "msg": "success",
  "data": { /* 具体数据 */ }
}
```

**错误响应**：

```json
{
  "code": 400,
  "msg": "错误描述",
  "data": null
}
```

### 5.2 请求拦截与响应处理

**请求拦截器 (Axios Interceptor)**：

- 自动在请求头添加 `Authorization: Bearer <token>`
- 请求失败时自动重试（可选）

**响应拦截器**：

- `code = 0`：正常返回 `response.data.data`
- `code ≠ 0`：抛出错误，显示错误提示（Element Plus Message）
- `401`：Token 失效，跳转登录页
- `403`：无权限操作，显示权限不足提示
- `500`：服务器错误，显示服务端异常提示

## 9. 流式响应实现方案

### 9.1 技术方案

使用 `fetch` API 配合 `ReadableStream` 读取流式响应：

```javascript
async function* streamChat(query) {
  const response = await fetch('/api/v1/chat/ask/stream', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'Authorization': `Bearer ${token}`
    },
    body: JSON.stringify({ query, knowledgeBaseIds: selectedIds })
  })

  const reader = response.body.getReader()
  const decoder = new TextDecoder()

  while (true) {
    const { done, value } = await reader.read()
    if (done) break

    const chunk = decoder.decode(value)
    // 解析 SSE 格式数据
    // yield chunk
  }
}
```

### 9.2 SSE 数据格式处理

后端返回的流式数据为 SSE 格式：

```
data: {"content": "你好"}

data: {"content": "，"}

data: {"content": "有什么"}

data: {"code": 0, "msg": "success", "data": {"type": "end", "chatId": "xxx"}}
```

前端需要：

- 解析 `data:` 前缀
- 提取 `content` 字段逐步显示
- 识别 `type: 'end'` 信号表示流结束
- 处理可能的错误数据

### 9.3 流式状态管理

- `isStreaming`：控制输入框状态，防止重复提交
- `当前消息缓冲`：收集流式数据，组成完整回答
- `引用提取`：从回答中提取引用信息
- `中断处理`：支持用户取消请求（`AbortController`）

## 11. 错误处理规范

### 11.1 前端错误分类

| 错误类型 | 处理方式 | 用户提示 |
|---------|---------|---------|
| 网络错误 | 捕获异常 | "网络连接失败，请检查网络" |
| 401 错误 | 跳转登录 | "登录已过期，请重新登录" |
| 403 错误 | 提示权限 | "您没有权限执行此操作" |
| 404 错误 | 提示资源 | "请求的资源不存在" |
| 500 错误 | 提示服务端 | "服务器异常，请稍后重试" |
| 业务错误 | 显示 msg | 显示后端返回的错误信息 |

### 11.2 统一错误处理

**Element Plus Message 提示**：

```javascript
import { ElMessage } from 'element-plus'

ElMessage.error({
  message: '错误信息',
  duration: 3000
})
```

**请求错误拦截**：

```javascript
// 响应拦截器
axios.interceptors.response.use(
  response => response,
  error => {
    if (error.response) {
      switch (error.response.status) {
        case 401:
          // Token 失效处理
          break
        case 403:
          ElMessage.error('没有权限')
          break
        default:
          ElMessage.error(error.response.data.msg || '请求失败')
      }
    } else {
      ElMessage.error('网络连接失败')
    }
    return Promise.reject(error)
  }
)
```
